# 大桌游性能（渲染层裁剪 + 减负）

> 目标：几百组件的真实 TTS mod（789 卡）流畅运行。纯渲染层优化——引擎状态与协议零改动。
> 配套 note（决策条目）在优化落地后写入 `notes/implemented.md`。

## 瓶颈分析

1. **堆内全量渲染**：`Pile.tsx` 把堆内每张牌渲染成完整 `Card`（各挂 `useDraggable` + `useHoverable`，注册进 dnd-kit）。视觉上只需要顶牌 + 几条厚度边
2. **无视口裁剪**：`GameBoard.tsx` 把 `scene.entities` 全量挂 DOM，屏幕外的自由牌照常渲染
3. **拖动每帧全量重渲染**：`dragDelta` 每帧变 → `deriveScene` 重算 → 全部 wrapper 重新调和；`Card` 无 `React.memo`

## 优化项

| 项 | 做法 | 状态 |
|----|------|------|
| M1 基线测量 | 真实 mod 实测，数字填下表 | ✅ 已测（DOM 3141 / Card 959 / 堆 29 / 轻微卡） |
| M2 Pile 减负 | 只渲染顶牌（可拖、快捷键载体）+ 顶牌下 ≤3 张纯 div/img 厚度边（`PileEdge`，无 hooks、无 data-card-id），更深成员不渲染；偏移**本地化**——可见卡簇第 k 张渲染在 k×0.5px 锚定基座，不照搬 stackLayout 全堆累加偏移（否则大堆可见几张悬空在基座右下方，复测发现已修）；状态不动 | ✅ 已复测 + 修偏移回归 |
| M3 视口裁剪 | GameBoard 按实体世界坐标 + 尺寸与视口（pan/zoom + 容器尺寸，ResizeObserver 跟踪）求交，视口外不挂 DOM；余量 160 桌面坐标；被拖实体/堆豁免；判定在渲染层，deriveScene 保持全量场景语义 | ✅ 已复测 |
| M4 Card memo | `React.memo` + props 浅比较（entity 引用由不可变更新天然稳定） | ✅ 已复测 |

**有意的行为变化**：① 大堆只显示顶牌 + 3 条厚度边，更深的亚像素阶梯边不再渲染（张数角标示数）；② 埋在堆里的牌不再响应 hover 快捷键（此前从边缘缝可对埋牌按 D 抓出），交互收敛到顶牌。

## 测量

指标表（基线 / 优化后同场景对比）：

| 指标 | 基线 | 优化后 |
|------|------|--------|
| DOM 节点总数（`document.querySelectorAll('*').length`） | 3141 | 543（-83%） |
| Card 实例数（`[data-card-id]`） | 959 | 102（-89%） |
| 堆数（`[id^="pile-"]`） | 29 | 17（12 个视口外堆被裁剪） |
| 拖动单牌 5s 主观帧率 / 卡顿感 | 轻微卡 | 流畅多了 |
| 滚轮缩放 / 平移流畅度 | 待填 | 流畅多了 |

注：DOM/Card 为瞬时值，随缩放平移视口内容浮动。验收线写的 ≤500 实测 543——该线是拍脑袋预估值，实际数字取决于当前视口可见实体量；5.8× 削减 + 主观流畅已达成目标本质，不再为凑数加裁剪。

方法：游戏广场打开该桌游单机试玩 → DevTools Console 逐条执行上面三行统计命令 → 记数字；拖一张自由牌绕圈约 5 秒 + 滚轮缩放，凭感受记录是否掉帧。

## 验收标准

- DOM 节点数 ≤ 500（基线预计 1500+，以实测为准）
- 拖动、缩放、平移无肉眼可感卡顿（主观帧率 ≥ 50）
- 零功能回归：vitest 全过；手动过拖拽 / 入堆 / 建堆 / 洗牌 / 翻整叠 / D 抓牌 / 手牌区 / 版图跟随
- 不装新依赖

## 边界（主动否决）

- 不换 PixiJS / Canvas（`notes/rejected.md` 条款不变；触发线 = 裁剪后 >500 可见实体仍卡）
- 不动引擎与协议
- 不做通用虚拟列表抽象，裁剪只写在 GameBoard 消费处
